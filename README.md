# Optimization-Based User Scheduling for Multiuser MIMO Systems

MATLAB simulation code for the numerical experiments in:

> V. Palhares and C. Studer, **"An Optimization-Based User Scheduling Framework for Multiuser MIMO Systems,"** *IEEE Trans. Wireless Commun.*, Nov. 2026, doi: [10.1109/TWC.2026.3754543](https://doi.org/10.1109/TWC.2026.3754543).

The simulator evaluates optimization-based user scheduling together with the baseline scheduling methods used in the paper for centralized millimeter-wave (mmWave) massive MU-MIMO and sub-6-GHz cell-free massive MU-MIMO systems.

## Branches

The `main` branch contains the frequency-flat simulations used for Scenarios S1-S6 and the additional T = 8 mmWave experiment reported in the paper.

The frequency-selective OFDM simulation reported in Table V is maintained separately on the `frequency-selective` branch. Users interested in reproducing that experiment should switch to the `frequency-selective` branch and follow the README provided there.

## Simulation scenarios

| Scenario | System | B | U | T | Tmin | Tmax | Umin | Umax |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| S1 | mmWave | 16 | 16 | 2 | 1 | 2 | 8 | 10 |
| S2 | mmWave | 32 | 32 | 2 | 1 | 2 | 16 | 20 |
| S3 | mmWave | 32 | 64 | 4 | 1 | 2 | 16 | 20 |
| S4 | Cell-free | 16 | 16 | 2 | 1 | 2 | 8 | 10 |
| S5 | Cell-free | 32 | 32 | 2 | 1 | 2 | 16 | 20 |
| S6 | Cell-free | 32 | 64 | 4 | 1 | 2 | 16 | 20 |
| Additional mmWave experiment | mmWave | 32 | 64 | 8 | 1 | 4 | 8 | 10 |

Here, `B` is the total number of receive antennas, `U` is the number of UEs, and `T` is the number of resource slots. `Umin`/`Umax` and `Tmin`/`Tmax` are the scheduling constraints defined in the paper.

## Requirements

- MATLAB R2021b or a compatible newer release.
- MATLAB functionality providing `de2bi`, `randsample`, and `dftmtx`.
- Channel realization MAT files for the scenario being simulated.
- Sufficient storage for the per-job result MAT files generated by the Monte Carlo simulations.

The paper simulations use 1,000 channel realizations and 100,000 Monte Carlo trials per channel realization for the CDF/CCDF results.

## Paths to configure before running

Before running a simulation, edit **two paths in the MATLAB source**. The line
numbers below refer to this repository version.

### 1. Channel MAT-file path

Edit **line 22** of:

```text
Main_simulator/channel/gen_channel.m
```

The current line begins with:

```matlab
FileLoad=['/path/to/channel/',par.system_type,'_',num2str(par.B),'_',num2str(par.U),'/channels_',...
```

Replace only the root path

```text
/path/to/channel/
```

with the directory containing your channel MAT-file folders. Keep the remainder
of the filename construction unchanged.

For example, if the channel folders are stored under
`/data/ue_scheduling/channels/`, the line should begin with:

```matlab
FileLoad=['/data/ue_scheduling/channels/',par.system_type,'_',num2str(par.B),'_',num2str(par.U),'/channels_',...
```

The loader expects files following the naming convention

```text
channels_<system_type>_<B>_<U>_<channel_id>.mat
```

inside a system-size directory such as

```text
mmwave_16_16/
mmwave_32_32/
mmwave_32_64/
cell_free_16_16/
cell_free_32_32/
cell_free_32_64/
```

Each channel file must contain the channel matrix in the variable `H`.

### 2. Simulation result path

Edit **line 371** of:

```text
Main_simulator/main_function.m
```

The current line is:

```matlab
path_to_save = (['/path/to/results/']);
```

Replace

```text
/path/to/results/
```

with the directory where the per-job result MAT files should be written. The
path should end with `/`.

For example:

```matlab
path_to_save = (['/data/ue_scheduling/results/']);
```

The generated filenames have the form

```text
USER_SCHEDULING_<system_type>_<B>_<U>_T_<T>_<process_id>.mat
```

Channel and result MAT files are intentionally not tracked by Git.

### Paths used for post-processing

The two edits above are sufficient to **run the simulations**. To use the
provided `start_results.m` scripts afterward, also update the paths in the
scenario directory you are processing:

- **Line 23** of each `start_results.m`: set `par.main_path` to the absolute
  path of this repository's `Main_simulator/` directory.
- **Line 28** of each `start_results.m`: set the path passed to
  `plot_figures_cdf` to the directory containing that scenario's result MAT
  files.

The relevant files are:

```text
mmwave/16_16/start_results.m
mmwave/32_32/start_results.m
mmwave/32_64_T_4/start_results.m
mmwave/32_64_T_8_Tmax_4/start_results.m
cell_free/16_16/start_results.m
cell_free/32_32/start_results.m
cell_free/32_64_T_4/start_results.m
```

For the average-SNR calculations used for S1 and S4, also update:

- **Line 23** of `mmwave/16_16/start_calculate_average_SNR.m` and
  `cell_free/16_16/start_calculate_average_SNR.m`: set `par.main_path`.
- **Line 28** of those files: set the result directory passed to
  `calculate_average_SNR`.

## MATLAB path setup

Start MATLAB from the repository root and add the simulator to the MATLAB path:

```matlab
addpath(genpath(fullfile(pwd,'Main_simulator')));
```

Then move to the directory of the scenario that you want to run. For example:

```matlab
cd('mmwave/16_16');
```

## Running one simulation job

Each scenario directory contains a `main_sim_code.m` entry point that accepts a zero-based process ID. The process ID can be supplied as a numeric value or a string.

To run process 0 of Scenario S1:

```matlab
main_sim_code(0);
```

The simulation parameters and the scheduling method associated with the process ID are assembled automatically by `param_config.m` and `main_sim_code.m`.

## Running all jobs for a scenario

For a complete scenario, first determine the total number of jobs from the corresponding parameter configuration and then execute all zero-based process IDs. For Scenario S1, for example:

```matlab
par.plot_type = 'CDF';
par.system_type = 'mmwave';
par.sim_scenario = 'a';
par = param_config(par);

num_jobs = par.total_jobs;
for proc_ID = 0:num_jobs-1
    main_sim_code(proc_ID);
end
```

For large experiments, the process IDs can be distributed across independent MATLAB workers or compute nodes because each process writes a separate result file.

## Scenario entry points

Run the `main_sim_code.m` file in the corresponding directory:

| Experiment | Internal scenario code | Directory |
|---|---|---|
| S1 | `a` | `mmwave/16_16/` |
| S2 | `b` | `mmwave/32_32/` |
| S3 | `c` | `mmwave/32_64_T_4/` |
| T = 8 mmWave experiment | `d` | `mmwave/32_64_T_8_Tmax_4/` |
| S4 | `a` | `cell_free/16_16/` |

| S6 | `c` | `cell_free/32_64_T_4/` |

## Generating figures and percentile summaries

Each scenario directory contains `start_results.m` for post-processing the saved simulation jobs.

Before running it:

1. Set `par.main_path` to the absolute path of the repository's `Main_simulator/` directory.
2. Set the result directory passed to `plot_figures_cdf` to the directory containing the per-job MAT files.
3. Create a `figures` directory in the scenario directory if it does not already exist.

For example:

```matlab
mkdir('figures');
start_results;
```

The post-processing chain uses the functions in `Main_simulator/results/` to generate the CDF/CCDF figures and the 90th-percentile summaries reported in the paper.

For the S1 and S4 average-SNR values discussed in the paper, configure the paths in `start_calculate_average_SNR.m` and run that script from the respective `16_16` scenario directory.

## Generated files

Simulation and post-processing runs can generate files such as:

```text
parameters.mat
USER_SCHEDULING_*.mat
Metrics.mat
*_90_percentile.mat
*.fig
*.pdf
```

These are generated results and are excluded by `.gitignore` so that the repository contains only the source needed to run and post-process the simulations.
